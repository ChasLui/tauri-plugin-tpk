import { Card, CardGrid, Steps } from '@astrojs/starlight/components';

<CardGrid>
  <Card title="Nothing executable is written" icon="approve-check-circle">
    Packs are parsed out of a ZIP into memory and served through Tauri's `Assets` trait. No file the OS could execute, no dynamic library, no `$RESOURCE`.
  </Card>
  <Card title="A bad release can't brick the app" icon="warning">
    A revision is on trial until the frontend acknowledges it. Three unacknowledged launches and it is rolled back and blacklisted.
  </Card>
  <Card title="Layers, not replacements" icon="puzzle">
    `base` / `patch` / `dlc` stack over the embedded assets. bsdiff deltas and deletion tombstones mean a hotfix is kilobytes, not megabytes.
  </Card>
  <Card title="Static files, no service" icon="rocket">
    A signed channel manifest and some `.tpk` files on any CDN. No API, no session, no vendor.
  </Card>
</CardGrid>

## Quick start

<Steps>
1. **Configure** the plugin → [Configuration](/tauri-plugin-tpk/configuration/)
2. **Publish** a channel → [Server Contract](/tauri-plugin-tpk/server-contract/)
3. **Build & sign** a pack → [Packaging](/tauri-plugin-tpk/packaging/)
4. **Wire** the frontend API → [API Reference](/tauri-plugin-tpk/api-reference/)
5. **Test** it, including the rollback → [Local Testing](/tauri-plugin-tpk/local-testing/)
</Steps>

## Before you ship to a store

This is not a way around app review. Anything that changes what the app *does*
belongs in a store release.

Read [Security](/tauri-plugin-tpk/security/) for where the line is and who drew
it, and work through the
[App Review Checklist](/tauri-plugin-tpk/app-review-checklist/) before you
submit.

Upgrading from the previous plugin? See
[Migrating](/tauri-plugin-tpk/migrating-from-hotswap/) — it is a rewrite, not a
drop-in swap.
